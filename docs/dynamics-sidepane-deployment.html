Implementation guide · 28 August 2026

Put the streamed agent beside the CRM record.

A guided deployment path for the GHCP-harness Copilot Studio agent already proven through the experimental Agentic Runtime /3p SSE route. Dynamics 365 owns the pane and record context; the hosted widget owns the conversation; a hardened relay owns authentication and the remote transport.

Target outcome

A closable 420 px model-driven app side pane, opened from a command bar, preserving one conversation while users move between CRM records and rendering real progressive response activities rather than a cosmetic typewriter.

△
Production gate: the /3p route is experimental.

Microsoft Learn currently documents Copilot Studio Client support for standard-harness agents and says GHCP-harness agents are not yet officially supported. Treat this design as an internal pilot until Microsoft confirms the `/3p` support contract, SLA, and production use for your tenant. Keep a supported Teams, Microsoft 365, or Web app fallback.

Reference architecture

Five ownership boundaries

Keep Dynamics customization thin. Do not copy the SDK, `/3p` URL, or tokens into a Dataverse web resource. The web resource only creates the side pane, supplies non-secret record context, and embeds the independently deployed widget.

01 Dynamics 365 Command bar, active record, pane lifecycle
02 HTML launcher Solution web resource; embeds one trusted HTTPS origin
03 Chat widget Responsive Web Chat UI, MSAL popup, stream coalescing
04 Node relay Inbound token validation, OBO, session routing, diagnostics
05 Copilot Studio Allowlisted GHCP agent over authenticated `/3p` SSE
Identity path: signed-in CRM user → widget API access token → relay validates user and client → relay obtains Power Platform token through OBO → `/3p` enforces the target Agent and user access. The browser never receives an app secret.

Before implementation

Make these decisions explicit

Recommended pilot

Deploy this Node/Express app as one HTTPS origin on Azure App Service. Load that public shell in the pane, require Entra before chat, and protect every relay API call.

Supported fallback

Keep a Teams, Microsoft 365, or documented Web app launch available if `/3p` changes or Microsoft doesn't approve the experimental route for production.

Do not ship the playground as-is

The current page exposes diagnostic routing controls, stores user tokens in browser local storage, uses in-memory sessions, and enables full raw response capture by default.

Agent targeting

Pin one environment ID, schema name, cloud, and exact `/3p` path on the server. Never accept a browser-supplied host or Direct Connect URL in the production widget.

Solution web resource

Command-bar pane controller

Add this as {prefix}_/agent/openPane.js. It reuses one pane, passes only non-secret record context, and uses the documented Xrm.App.sidePanes API. Configure the modern command to pass PrimaryControl into AgentPane.open.

openPane.js
var AgentPane = (function () {
  "use strict";

  var paneId = "contoso_streamed_agent";
  var webResourceName = "contoso_/agent/launcher.html";

  function cleanGuid(value) {
    return (value || "").replace(/[{}]/g, "");
  }

  async function open(primaryControl) {
    var formContext = primaryControl;
    var entity = formContext && formContext.data && formContext.data.entity;
    var globalContext = Xrm.Utility.getGlobalContext();
    var context = {
      entityName: entity ? entity.getEntityName() : "",
      recordId: entity ? cleanGuid(entity.getId()) : "",
      appId: globalContext.getCurrentAppProperties
        ? (await globalContext.getCurrentAppProperties()).appId
        : "",
      organizationUrl: globalContext.getClientUrl()
    };

    var pane = Xrm.App.sidePanes.getPane(paneId);
    if (!pane) {
      pane = await Xrm.App.sidePanes.createPane({
        title: "AI assistant",
        paneId: paneId,
        canClose: true,
        width: 420,
        alwaysRender: true
      });
    }

    await pane.navigate({
      pageType: "webresource",
      webresourceName: webResourceName,
      data: encodeURIComponent(JSON.stringify(context))
    });
    pane.select();
  }

  return { open: open };
})();
Record changes

Re-run the same command when a user wants the new record applied. If you later add automatic record synchronization, use a documented form event and exact-origin postMessage; don't reach into the external frame's DOM.

Solution web resource

Minimal iframe launcher

Add this as {prefix}_/agent/launcher.html. Replace the widget origin with the deployed HTTPS origin. The embedded route must be publicly loadable as a shell; authentication happens through the widget's user-initiated MSAL popup and protected API calls.

launcher.html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width,initial-scale=1" />
  <title>AI assistant</title>
  <style>
    html, body, iframe { width: 100%; height: 100%; margin: 0; border: 0; }
  </style>
</head>
<body>
  <iframe id="agentFrame" title="AI assistant"></iframe>
  <script>
    (function () {
      var trustedWidgetOrigin = "https://agent-widget.contoso.com";
      var params = new URLSearchParams(window.location.search);
      var raw = params.get("data") || "";
      var context = {};

      try {
        context = JSON.parse(decodeURIComponent(raw));
      } catch (error) {
        console.error("Invalid pane context", error);
      }

      var widgetUrl = new URL("/crm-pane", trustedWidgetOrigin);
      ["entityName", "recordId", "appId", "organizationUrl"].forEach(function (key) {
        if (context[key]) widgetUrl.searchParams.set(key, context[key]);
      });

      document.getElementById("agentFrame").src = widgetUrl.toString();
    })();
  </script>
</body>
</html>
Authentication change required

This repository currently uses full-page acquireTokenRedirect. Replace that on the pane route with acquireTokenSilent followed by a user-clicked acquireTokenPopup. Entra sign-in pages cannot be rendered inside the CRM iframe. Use sessionStorage rather than localStorage for the widget token cache.

Release controls

Security requirements

Identity

Single tenant, delegated user access, OBO at the relay, exact issuer/audience/client validation, Conditional Access, and no browser secret.

Agent authorization

Share the Agent to a pilot security group. Keep environment/schema/path server-side and reject every other target before network I/O.

Browser boundary

Allow only the exact CRM origin in frame-ancestors. Validate postMessage origin, source, and payload. Never use *.

Data handling

Disable raw capture, redact telemetry, minimize record context, define transcript retention, and classify prompts as customer data.

Runtime

Bound request size and duration, rate-limit by user, map conversations to owners, use distributed state for scale-out, and expire idle sessions.

Operations

Health checks, deployment slots, App Insights without content, alerts on auth and upstream failures, feature flag, and tested fallback.
