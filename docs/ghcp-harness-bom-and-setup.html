Deployment runbook

Manifest & setup guide · 28 August 2026

Everything you need to stand this up — and the order to do it in.

This deck is the parts list and the assembly instructions for embedding a GHCP-harness Copilot Studio agent as a Dynamics 365 side pane. Part one is the bill of materials: every Azure resource, identity object, Dataverse component, source file and configuration key. Part two is the ordered runbook that turns those parts into a working experience.

What you end up with

A command-bar button on a model-driven form that opens a 420 px side pane. The pane signs the user in silently against their existing Dynamics session, streams progressive responses from an authenticated agent over the Agentic Runtime /3p route, and renders sanitised Markdown — with the agent pinned server-side so the browser cannot redirect it.

△
The /3p route is experimental. Treat this as an internal pilot.

Microsoft Learn documents Copilot Studio Client support for standard-harness agents and states that GHCP-harness agents are not yet officially supported. Confirm the support contract and SLA for your tenant before production use, and keep a supported Teams, Microsoft 365 or Web channel fallback.

Orientation

Five tiers, four trust boundaries

Read the bill of materials against this layout. Each tier owns exactly one concern, and the parts list is grouped the same way.

Tier 1 · Host
Model-driven app (Dynamics 365)

Owns the command bar, the side pane and the record context. Contributes the ribbon button and three web resources. Never sees a token.

Tier 2 · Bridge
Launcher web resource

A same-origin HTML shim. Dynamics can only host web resources from its own origin, so this page frames the externally hosted widget and forwards non-secret context.

Tier 3 · Client
Hosted widget (App Service)

Acquires a delegated token via MSAL, streams NDJSON from the relay, and renders Markdown through a strict DOMPurify allow-list. Served with a CSP that pins frame-ancestors to your Dynamics origin.

Tier 4 · Relay
Node relay (same App Service)

Pins the agent server-side, inspects the delegated token, rate-limits per subject, and holds conversation sessions bound to the token subject. Re-validates the outbound /3p URL against an SSRF guard on every call.

Tier 5 · Agent
Copilot Studio Agentic Runtime

The real authorization boundary. The relay is not the token audience — /3p validates the user token and enforces agent sharing. An unshared agent returns 403 no matter how cleanly the user authenticated.

Why the relay is not the security boundary. The relay inspects the delegated token to fail fast and to key its session map, but it does not mint, exchange or downgrade it. Removing the relay's checks would not grant a caller any additional access at the agent — it would only make failures louder and later.

Missing keys disable the pane; malformed keys crash the boot. That split is intentional. An unconfigured pane returns enabled: false so the rest of the app keeps running, but a misconfigured one fails loudly at startup rather than serving a widget that can never reach its agent.

Part two

Setup steps

Follow in order — steps 4–7 have hard dependencies on the identifiers produced by 1–3. Progress is stored in this browser only.

Microsoft Entra admin center

1 · Register the single-page application

Create a new app registration, single tenant. Under Authentication, add a platform of type Single-page application and register the redirect URI https://<app>.azurewebsites.net/crm-pane. Add http://localhost:3978 only if you develop locally.

Do not create a client secret and do not add a Web platform. Record the Application (client) ID and Directory (tenant) ID.

Microsoft Entra admin center

2 · Grant the delegated Power Platform permission

Under API permissions, add Power Platform API → Copilot Studio → Delegated → CopilotStudio.Copilots.Invoke, then grant admin consent for the tenant.

  • It must be delegated. The /3p endpoint rejects app-only tokens outright.
  • Leave app roles empty — the agent, not this registration, decides who may talk to it.
  • If the Power Platform API does not appear, register the service principal in the tenant first.
Copilot Studio

3 · Publish and share the agent, then capture its identifiers

Set the agent's authentication to Authenticate with Microsoft, publish it, and share it with every pilot user. Then record the environment ID and the agent schema name — not the display name.

Sharing is the single most common cause of a working sign-in followed by a 403. Verify it now rather than during end-to-end testing.

Azure CLI

4 · Provision the Azure infrastructure

Deploy the Bicep template to create the plan, web app, Application Insights and Log Analytics workspace. Keep real parameter values in a git-ignored main.parameters.local.json. 

az deployment group create \
  --resource-group <rg> \
  --template-file infra/main.bicep \
  --parameters @infra/main.parameters.local.json
Azure CLI

5 · Apply the configuration keys

Set every required PANE_* setting in one call, before deploying code. PANE_DYNAMICS_ORIGINS must be the bare origin of your Dynamics environment. 

az webapp config appsettings set -g <rg> -n <app> --settings \
  PANE_TENANT_ID=<tenant-guid> \
  PANE_CLIENT_ID=<client-guid> \
  PANE_ENVIRONMENT_ID=<environment-guid> \
  PANE_SCHEMA_NAME=<agent-schema-name> \
  PANE_DYNAMICS_ORIGINS=https://<org>.crm.dynamics.com \
  PANE_AGENT_DISPLAY_NAME="AI assistant"
Do this before the deploy, not between deploy and restart. Changing an app setting restarts the SCM container; if a deployment is in flight it aborts with "Deployment has been stopped due to SCM container restart".
Local shell

6 · Package and deploy the relay

Build the zip with forward-slash entry names and push it to the deployment endpoint. Then restart the app.

Do not use Compress-Archive on Windows. It writes backslash path separators into the archive. Oryx will build with zero errors and the deployment will then fail at the file-sync stage with failed to stat "/home/site/wwwroot/public\app.js": Invalid argument (22), surfacing only as a bare "Deployment Failed". Use [System.IO.Compression.ZipFile] and replace \ with / in each entry name, then assert the backslash count is zero.

A restart is required whenever you change anything evaluated at module load — the CSP string is built once when the router is created, so a code-only deploy will serve static assets from the new build while still emitting the old header.

Browser

7 · Smoke-test the hosted widget standalone

Before touching Dynamics, confirm the widget stands on its own. Open https://<app>.azurewebsites.net/crm-pane directly and check:

  • The header shows your agent display name and the composer is disabled until sign-in.
  • /api/pane/config returns 200 with your client and tenant IDs.
  • /crm-pane.html returns 404 — the shell must never be served by static middleware.
  • The response carries frame-ancestors for your Dynamics origin and no X-Frame-Options header.
Dataverse

8 · Create the publisher and the web resource solution

Create a publisher with your chosen prefix, then an unmanaged solution containing the three web resources. Before uploading launcher.html, replace its WIDGET_ORIGIN placeholder with your deployed origin — the file ships with a deliberate placeholder and a runtime guard that renders a configuration error if you forget.

  • <prefix>_/agent/openPane.js — JavaScript
  • <prefix>_/agent/launcher.html — HTML
  • <prefix>_/agent/agent-icon.svg — SVG

Publish the solution before continuing.

Dataverse

9 · Add the command bar button

Add a RibbonDiffXml customisation to the target table binding a button to AgentPane.open in openPane.js, passing PrimaryControl as its only parameter. Import, then run a publish.

  • <Entity><Name> must be the Pascal-case schema name (Incident, not incident), and must match the RootComponent entry — otherwise the import fails with 0x80048008.
  • The solution must carry the full exported entity node. A minimal <EntityInfo><entity Name="…" /></EntityInfo> is rejected with 0x80040203. Export a throwaway solution containing the table, graft your RibbonDiffXml over the empty one, and re-import.
  • Confirm the table is a component of the app module you intend to test in.
Model-driven app

10 · Enable and verify end to end

Open a record of the target table as a non-admin pilot user, hard refresh, and use the button. Work through the verification table below before declaring the pilot ready.

If the button is missing, check the ⋯ overflow menu first and clear the ribbon cache with ?flags=byPassCache=true — model-driven apps cache ribbon definitions aggressively.

Field notes

Known failure modes

Every entry below was hit during the build. The symptom rarely names the cause, which is why they are worth listing.

SymptomCauseFix
"Deployment Failed" with a clean Oryx build Zip contains backslash path separators. Rebuild with ZipFile + forward slashes; assert zero backslash entries.
Deployment has been stopped due to SCM container restart An app setting changed while the deploy was in flight. Apply settings first, then deploy.
New code live, old CSP header The CSP string is built at module load. Restart the web app after deploying router changes.
Sign-in popup every time, silent SSO never fires CSP default-src 'self' blocks the hidden Entra iframe. Add frame-src https://login.microsoftonline.com.
Solution import fails 0x80048008 <Entity><Name> is lower-case, or disagrees with RootComponent. Use the Pascal-case schema name consistently.
Solution import fails 0x80040203 Minimal EntityInfo node. Graft the ribbon onto a full exported entity node.
Ribbon imports and publishes, button not visible Client-side ribbon cache, or the button is in the overflow menu. Hard refresh or ?flags=byPassCache=true; check ⋯.
403 from /3p after a clean sign-in Agent not shared with the user. Share the agent in Copilot Studio.
401 with a valid-looking token App-only token, or wrong audience. Use a delegated token for the Power Platform API.
Xrm.App.sidePanes undefined Multi-session app host restriction. Validate in a single-session app first.
